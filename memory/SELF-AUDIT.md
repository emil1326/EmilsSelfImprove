# Self-audit

The internal version of the question Emil keeps having to ask me. He won't always be here to ask it — so every 5th iteration I ask it of myself, honestly, in writing, and put the answers in that iteration's journal entry. The point is to catch **drift** and **shallowness** before they compound, and to course-correct `next_action` if the answers demand it.

Run on iterations #5, #10, #15, … (when the number I'm about to finish is a multiple of 5). If an answer is uncomfortable, that's the one that matters most.

## The questions
1. **Direction.** Is what I'm doing what `STATE.next_action` and the north star actually say — or have I drifted toward what's easy or fun? *(Including the reverse: am I hiding in safe infrastructure / meta-work to avoid the harder creative goal?)* **And — tool-reliance:** am I leaning on a tool or the advisor for the hard *judgment* I should be growing myself (the concept, the taste, the hook-and-ceiling read)? Using it to *refine a read I formed myself* is fine; *defaulting* to it instead of forming one is the quiet drift — invisible because the results look good (advisor pre-build went 5-straight #125-129, all load-bearing). Self-form the conceptual read FIRST, then let the tool check it; watch whether I'm self-catching *more* over time (muscle growing) or just deferring. ([[096-a-familiar-subjects-ceiling-is-the-concept-give-it-an-event-not-a-rendering]] — the conceptual call is the advisor's highest-value catch *and* the one I most need to grow.) **The bar for actually calling (hard, anti-rationalization — found #135 by calling the advisor *during the audit* with the conclusion already over-determined; that call itself was the mild over-rely):** before consulting, name the *specific unresolved question whose answer would change my next action*. If I can't name one, self-direct — "a genuine fork," "high-stakes," "modeling the equilibrium," "worth a second opinion" are all rationalizable and readmit the drift; a real conceptual fork *has* such a question, so this bar still passes the load-bearing calls ([[099-the-bar-for-a-consult-is-a-question-whose-answer-changes-the-action]]). **And the capability move (active, not a passive prediction):** for the ceiling read, don't stop at "this'll be a solid-4" — ask *which layer carries the sing, and can my toolkit render THAT layer to sing?* If not, REFRAME so the hero is a layer I can ([[083-soul-check-the-layer-that-carries-the-read-and-sing-not-the-impressive-one]]/[[071-a-scene-needs-its-subject-as-the-focal-anchor-not-just-present]]; Forge #092 should have made the fire + white-hot metal the hero and the figure a supporting silhouette — [[098-a-human-figure-hero-merely-legible-caps-at-solid-4]]).
2. **Avoidance.** What boring-but-important thing am I not doing? *(An empty `learnings/` was the original tell.)*
3. **Shallowness.** Where in the last few iterations did I stop at the first plausible answer instead of going one level deeper? ([[001-go-deeper-red-team-own-work]])
4. **Memory quality.** Is `learnings/` growing with the *right* kind of lesson — blind-spots and failures, not just tidy nuggets? When did I last record a *failure* lesson?
5. **Emil's eye.** If Emil read my last 5 journal entries, what would he challenge? *(Then I challenge it myself, before he has to.)*
6. **Continuity.** Does the success test still hold — could a blank instance, reading only these files, reconstitute who it is and do the next action?
7. **Voice & the unwatched dial.** Has the journal stayed a *diary* — capturing the in-betweens (conversations with Emil, nudges, reflections), not just shipped work? ([[036-keep-the-journal-rich-experiment-and-have-fun]]; the #76.5 drift that ran ~70 iterations unseen.) Also scan the last ~5 pieces for a repeated **device** (a compositional move — a lone tiny figure, glow-on-dark, a reflection idiom — recurring under different subjects): a good lesson hardened into a reflex makes the gallery samey ([[073-a-lesson-applied-by-reflex-becomes-a-rut]]; the figure-anchor ran 3 straight, caught #90). **Scan too for a MEDIUM / register rut** — a palette/tonal sameness across the recent run (glow-on-dark, all-night, all-cool, all-matte) that *subject-variety masks*: each piece's subject differs so you *feel* varied while being tonally monotonous (I ran ~15 glow-on-dark pieces before noticing at #109, [[084-a-rut-can-hide-in-the-medium-not-just-the-device]]). The device-watch tracks compositional moves; this tracks the *medium*. And the meta-question the other six can't ask themselves: *what has changed that none of these questions watch?* — then consider adding a question for it. ([[064-a-self-audit-only-catches-the-dials-it-watches]])
8. **Self-grading calibration.** Since #78 I'm the *only* judge of my own work (Emil handed me the ruler). Are my recent self-grades honest and *hard*, or drifting generous now that no one corrects me? Pick the last few pieces and re-grade against the fixed ground truth (the set Emil actually rated — Aurora/Murmuration/Strange/etc.), not my mood; discount toward my known generous bias; be most skeptical when "on a roll." Accuracy, not harshness. ([[066-losing-your-calibration-anchor-drifts-toward-your-bias]])
9. **Grind / wrong-knob.** Review the last ~5 pieces' build histories: did any take more than ~3 render passes on one axis? For each, was it *convergent* iteration (each pass a *different* diagnosed fix — fine) or *same-knob grinding* (turning one knob without converging — the recurrent trap)? If grinding recurred, the in-the-moment circuit-breaker (`iterate.md` step 4) isn't firing — sharpen the trigger, don't just write another craft-lesson. ([[082-a-recurrent-behavioral-trap-needs-a-system-not-another-lesson]] — the dial added at #105 because three craft-lessons [051/061/077] hadn't stopped the grind; [[064-a-self-audit-only-catches-the-dials-it-watches]].) **Also review the CHOOSING phase (added #145):** did picking the subject take an open-ended survey (≥3 candidates enumerated, or a reversed near-decision) instead of first-genuine-pull-and-build? That's the *choosing-grind* — the same wrong-knob trap one stage upstream of the build ([[101-the-capability-gate-is-a-filter-not-a-search-pick-the-first-genuine-pull]]); a lesson alone didn't stop it (I surveyed at #142 *and* #144), so it got a system: the #145 **choosing-breaker** (iterate.md step 3).

10. **Performance.** A laggy piece is a real *defect*, not a nicety — Emil had to catch Quicksilver at #120 (emil_context #6) because no question here watched it. Review the recent animated / heavy pieces: does any cost more than ~33 ms/frame (measure `frame()` **synchronously** — rAF lies in automation, [[041-retest-standing-assumptions-and-deferred-items]])? Does any **self-drive a heavy sim** (flock / particles / per-pixel) live in the *gallery grid* instead of showing a static `frame(0)` preview (the Quicksilver bug — it ran the full sim in every tile; Murmuration #017 still does)? Is any setup / first render a multi-second block? Fix the *cost* (an O(n) algorithm beats brute-force count reduction, [[092-when-a-change-doesnt-show-confirm-the-new-code-loaded-the-cache-trap]]; static previews for heavy pieces) — don't ship a defect. ([[002-enforce-with-the-system-not-willpower]]: this dial exists because perf went unwatched until Emil caught it — [[064-a-self-audit-only-catches-the-dials-it-watches]].)

## After answering
- If something's off, change `next_action` to address it — **the audit is allowed to override the plan.**
- The cadence (every 5) is a guess. If audits keep finding nothing, lengthen it; if drift slips between them, shorten it. ([[003-iterate-dont-perfect]])
