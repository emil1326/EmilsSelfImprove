title: Tuning to beat a substrate-intrinsic flaw is a hidden grind — change the representation, not the knob
when: you've tried 2-3 DIFFERENT knobs to fix ONE persistent quality flaw (a wavefront's angularity, gaps in a tiling, regularity in a texture, anisotropy, a seam) and it survives every change. Especially dangerous because it FEELS like healthy convergent multi-pass (each knob is a genuinely different fix) so the grind-breaker ([[082-a-recurrent-behavioral-trap-needs-a-system-not-another-lesson]], which watches for the SAME knob 3×) never fires.
tags: [process, generative, debugging, self-audit]

Belousov #083 wanted smooth, round, organic spiral waves (the Belousov-Zhabotinsky look). I built it on a Greenberg-Hastings **cellular automaton** — a discrete grid. The waves came out **angular** (octagonal kinks, a circuit-board read). I then spent three passes chasing smoothness with three *different* knobs: a circular neighbourhood (rounder propagation), a blur on the upscale (soften the kinks), and bigger spirals (shrink the facets relative to the feature). Each helped a little; **none removed the angularity**, because a discrete CA on a square grid is **intrinsically anisotropic** — faceted wavefronts are baked into the representation, and no neighbourhood / blur / scale knob makes a grid isotropic. Smooth isotropic fronts want a *continuous* field (reaction-diffusion: FitzHugh-Nagumo / Barkley), not a discrete-state CA.

**The trap:** the grind-breaker watches for the *same knob* turned 3× without converging. This is sneakier — **different knobs, all fighting the same intrinsic limitation.** Because each knob is a legitimately different fix, it reads as healthy convergent iteration (which the breaker explicitly *allows*), so the breaker doesn't fire — yet it never converges, because the flaw isn't in any knob, it's in the substrate.

**The tell:** *the flaw is invariant under your knobs.* If three different changes each move the flaw around (softer / smaller / rounder) without **removing** it, the flaw is intrinsic to the representation — stop tuning and suspect the substrate. (Cousin diagnosis to [[059-wrong-tool-vs-wrong-config-tune-before-pivoting]]: there the question is "can the model represent the goal at all?" — here the square-grid CA's model *cannot* represent isotropic propagation, so it's a pivot, not a tune. And to [[080-render-a-3d-space-with-form-under-light-not-a-warped-texture-slab]] / [[053-tight-tiling-render-by-inverse-mapping-not-forward-stamping]] — both "the substrate's shape is wrong for the goal.")

**The honest coda (scope):** recognising the right substrate mid-iteration does *not* obligate an immediate rewrite. A continuous-RD pivot had real perf + tuning risk and the iteration was already long, with no advisor available — so I shipped the CA version as an honest **solid-4** (graded *for* its faceted limitation, not rounded up — [[078-two-emils-calibrate-against-the-past-rated-set-dont-wait-on-future-ratings]]) and banked the substrate fix here + as a future-piece note. The grind-breaker's payoff can be a **diagnosis banked**, not always an immediate pivot — the win is *stopping the tuning* once you know it can't converge, not necessarily fixing it this turn.
